# Markdown 문법 — Dongding Blog (v1.6.0)

`src/lib/markdown.tsx` 의 자체 파서가 동작합니다. **이 문서에 적힌 표기만 작동**합니다 — Studio 미리보기와 글 상세는 같은 파서를 공유.

> Parser: `src/lib/markdown.tsx` · Scope: Studio + 글 상세 · Updated: 2026.10.14 · Version: v1.6.0

## 1. 개요

이전엔 Studio 미리보기 파서가 따로, 글 상세는 JSX로 직접 작성하는 구조였다. 결과적으로 **같은 글이 두 화면에서 다르게 보이는** 일이 잦았다 — 미리보기에서는 callout 이 깨지고 상세에서는 멀쩡한 식. v1.3.0 부터 `markdown.tsx` 한 벌이 양쪽을 담당한다.

그래서 **이 문서에 적힌 표기만 동작**한다. `<Callout>` 같은 JSX 태그, 체크박스, HTML 직접 임베드 — 전부 일반 텍스트로 떨어진다. 의도적으로 좁게 잡았다 — 작성하는 사람이 머릿속에 담을 수 있는 양.

**v1.6.0 변경**: 링크에 한 줄 설명을 달면 popover 로 뜬다(§4, `[문구](url "설명")`).
다른 글을 가리킬 때는 글 카드 줄이 기본이다(§8).

**v1.5.1 변경**: 그림 폭에 `{xs}`(120px)와 임의 px(`{240}`)이 생겼다(§9).

**v1.5.0 변경**: 링크 프리뷰 카드가 생겼다(§8) — 줄 하나에 주소만 두면 카드로
펼쳐진다. 문장 안의 맨 URL 도 이제 자동으로 링크가 된다. 예전 문서에 "자동링크
미지원"으로 적혀 있으면 그쪽이 낡은 것이다.

**v1.4.0 변경**: GFM 파이프 표가 **지원된다**(§7-2). 예전 문서에 "표 미지원"으로
적혀 있으면 그쪽이 낡은 것이다.

이 문법을 어겼는지는 `check_posts` MCP 도구가 규칙으로 잡아낸다 — 규칙 목록은
[RULES.md](RULES.md).

## 2. 기본 규칙

| RULE | 내용 |
|------|------|
| RULE-01 | **마커 뒤엔 공백 한 칸**. `# 제목`, `> [!INFO]`, `- 항목` — 모두 마커 다음에 공백이 와야 한다. `#제목` 은 그냥 단락. |
| RULE-02 | **`>` 는 callout 전용**. 일반 인용문(blockquote) 미지원. `>` 로 시작하는 줄은 항상 callout 으로 해석. |
| RULE-03 | **JSX 태그는 안 받는다**. `<Callout>`, `<br>` 같은 태그는 그대로 텍스트로 출력. |
| RULE-04 | **블록 사이엔 빈 줄**. 헤더·코드 블록·callout·리스트 사이엔 빈 줄 한 줄. 없어도 대부분 동작하지만 단락이 들러붙는 경우. |

## 3. 헤더

H1 부터 H4 까지. **H2·H3 만 자동으로 TOC 에 들어감**.

| 표기 | 의미 |
|------|------|
| `# 제목` | H1 — 글 첫머리. 글 제목과 별개로 본문에서 큰 표제 쓸 때. |
| `## 섹션` | H2 — 가장 자주 쓰는 단위. **TOC 에 표시됨.** |
| `### 하위 섹션` | H3 — 섹션 안의 소단락. **TOC 에 표시됨.** |
| `#### 작은 제목` | H4 — 보조용. TOC 엔 안 들어감. |

### 예시

```markdown
## fetch join 의 한계
### 페이징과의 충돌
```

## 6. Callout

GitHub · Obsidian 과 같은 표기. **네 종류** (`INFO` / `WARNING` / `TIP` / `NOTE`), 제목 + 멀티라인 지원.
접힌 칸 `MORE` 는 아래 "접힌 칸" 절.

형식: `> [!종류] 제목`. 다음 줄부터 `>` 로 시작하면 같은 callout 의 본문으로 이어진다. 빈 `>` 줄은 callout 안의 단락 구분.

### 예시

```markdown
> [!WARNING] MultipleBagFetchException
> `List` 를 두 개 이상 fetch join 하면
> Hibernate 가 거부한다.
>
> `Set` 으로 바꾸거나 `@OrderColumn` 을 쓰는
> 우회법이 있다.
```

### 네 종류 (대소문자 무관)

| 종류 | 용도 |
|------|------|
| `> [!INFO]` | 맥락·전제·다루는 범위. 글의 시작에서 가장 자주. |
| `> [!WARNING]` | 사고로 이어질 수 있는 함정·흔한 실수·운영 위험. |
| `> [!TIP]` | 권장값·트레이드오프·측정 방법. "이렇게 하면 더 낫다". |
| `> [!NOTE]` | 본문 흐름과 떨어진 부연·다음 글 예고·관련 자료. |

### 제목 없이 쓰기

제목은 선택. `> [!INFO]` 까지만 쓰면 라벨만 나오고 제목은 빈다.

```markdown
> [!INFO]
> 본문만.
```

### 접힌 칸 — `> [!MORE] 제목`

일부 독자만 필요한 세부(환경별 예외, 같은 설정의 다른 표기, 확인 방법)를 닫힌 칸에 둔다.
닫힌 채 제목 한 줄만 보이니 제목은 **누구에게 필요한지**로 짓는다. 안쪽은 본문과 같은 문법으로
그리고, 코드 펜스도 `>` 를 붙여 쓴다. 읽기 시간·본문 분량에서 빠진다.

````markdown
> [!MORE] 설정 파일로 끄거나 꺼졌는지 확인하려면
> 첫 줄은 `~/.codex/config.toml`에 아래 두 줄을 쓰는 것과 같습니다.
>
> ```toml
> [features]
> daemon_auto_start = false
> ```
````

- 안쪽에는 문단·코드·표·목록만. 그림·이미지·소제목·링크 카드·다른 박스는 점검(`fold-content`)이 잡는다
- 쓰기 기준(릴리스·개념 글): 글당 셋까지, 칸마다 산문 600자 안쪽, 그 세부가 걸리는 섹션 끝에 둔다

### OK / 안 됨

```markdown
# OK
> [!INFO] 이 글이 다루는 범위
> Hibernate 6.x 기준이며…

> [!TIP]
> 측정부터 하자.
```

```markdown
# 안 됨
>hello                  ← 마커 뒤 공백 없음
> [WARNING] 제목         ← ! 빠짐
<Callout kind="info">    ← JSX 태그
>> 인용문                ← 일반 quote 미지원
```

## 7. 리스트 · 수평선

**한 단계만 지원**. 중첩 리스트는 안 받는다.

| 표기 | 의미 |
|------|------|
| `- 항목` | 불릿 리스트 |
| `1. 항목` | 번호 리스트. 첫 번호는 source 그대로 시작 (`2.` 도 가능) |
| `---` | 수평선. 단락 분리. |

### 예시

```markdown
동작 단계:

1. `em.find()` 시점에 스냅샷 저장
2. `flush()` 시점에 비교
3. 변경이 있으면 UPDATE 큐에
```

번호 리스트 바로 아래에 **들여쓰기 없이** `- ` 를 쓰면 그 번호 항목의 하위 불릿으로
붙는다. 들여쓴 `  - ` 는 리스트로 인식되지 않고 단락이 된다 — 규칙 `nested-list`.

```markdown
1. 스냅샷을 저장한다
- 필드 참조를 그대로 복제한다
- 컬렉션 mutate 는 비교가 어긋난다
2. flush 시점에 비교한다
```

## 7-2. 표 (v1.4.0~)

GFM 파이프 표. **헤더 바로 다음 줄에 구분행**이 있어야 표로 인식된다.
구분행이 없으면 그냥 단락으로 떨어진다 — 규칙 `broken-table`.

```markdown
| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `fetch` | LAZY | 연관 로딩 시점 |
| `cascade` | 없음 | 영속성 전이 |
```

- 셀 안에서 인라인 마커(`**굵게**`, `` `코드` ``, 링크)가 동작한다.
- 셀 안에 파이프를 넣으려면 `\|` 로 이스케이프.
- 가로 스크롤 컨테이너에 들어가므로 열이 많아도 레이아웃이 안 깨진다.
- 정렬 지정(`:---:`)은 구분행 판정만 통과할 뿐 정렬로 반영되지 않는다.

## 8. 링크 프리뷰 카드 (v1.5.0~)

**줄 하나에 주소만** 두면 카드로 펼쳐진다. 앞뒤로 빈 줄을 둘 것 — 다른 글자가 같은
줄에 있으면 그냥 단락이다.

| 표기 | 결과 |
|------|------|
| `https://example.com/글` | 외부 링크 카드 — 도메인 + 제목 + 설명 (+ 대표 이미지) |
| `/posts/some-slug` | 이 블로그의 글 카드 — 카테고리 · 날짜 · 요약 |
| 문장 중간의 `https://…` | 카드가 아니라 그냥 링크. 자동으로 걸린다 |

```markdown
관련 자료는 이쪽이 낫다.

https://vladmihalcea.com/hibernate-multiplebagfetchexception

앞 이야기는 여기서 했다.

/posts/jpa-n-plus-1
```

### 외부 카드의 제목·설명은 어디서 오나

글을 **저장하는 시점**에 서버가 그 주소의 OG 태그를 읽어 `link_meta` 표에 캐싱한다
(`src/lib/link-meta.ts`). 읽을 때는 이 표만 보므로 상세 페이지가 남의 사이트
응답속도에 묶이지 않는다.

- OG 가 없거나 크롤이 막힌 주소는 **도메인 + 경로 한 줄**로 축소된다. 카드가 사라지진 않는다.
- 캐시는 30일이 지나면 다음 저장 때 다시 읽는다.
- 사설망·`localhost` 주소는 요청 자체를 보내지 않는다.

### 내부 카드

`/posts/<slug>` 는 DB 에서 바로 읽으므로 OG 수집이 없다. **없는 slug 는 점선 박스**로
렌더된다 — 오타를 발행 전에 눈으로 잡으라는 뜻이고, `check_posts` 도 `missing-post-ref`
로 잡는다(error).

발행되지 않은 글을 가리키면 방문자에게는 점선 박스로 보인다. Studio 미리보기와 dev
환경에서는 draft 도 카드로 나온다 — 필자만 보는 화면이라서.

**짝 번호 (v1.6.0~).** 다른 글은 문장 속 링크로 걸고, 더 읽을 거리면 그 단락 바로 뒤에
같은 글의 카드 줄을 둔다. 렌더러가 링크와 카드에 같은 번호를 붙이고, 링크에 올리면 카드가
밝아진다. 카드만 두면 어느 문장의 더 읽을 거리인지 모른다(`check_release_voice` 의 `card-unpaired`).

```markdown
서버를 둘 수 있으면 [BFF가 토큰을 쥐는](/posts/jwt-storage-logout "JWT를 HttpOnly 쿠키로 옮기고 로그아웃을 처리하는 글") 편이 낫습니다.

/posts/jwt-storage-logout
```

링크 설명에는 그 글이 무엇을 다루는지 쓴다. `https://blog.dongding.dev/...`·`/preview/...` 주소는 쓰지 않는다.

## 9. 이미지

기본: `![설명](/posts/<slug>/<filename>)`

### 그림 블록과 너비

**줄에 이미지만** 있으면 캡션(alt) + 확대가 붙은 그림 블록이 된다. 앞뒤에 글자가
있으면 문장 안 인라인 이미지로 남는다. 이미지 줄이 연속되면 묶음(그리드)이다.

너비는 이미지 줄 끝의 `{...}` 로 지정한다.

| 표기 | 의미 |
|------|------|
| `![설명](url){xs}` | 120px — 뱃지·로고 |
| `![설명](url){sm}` | 380px |
| `![설명](url)` | 본문 폭 |
| `![설명](url){wide}` | 880px — 본문 밖으로 나간다 |
| `![설명](url){240}` | 임의 px. 5~1200 |
| `![a](url)` 연속 줄 + `{2}`~`{4}` | 묶음의 열 수 |

`{1}`~`{4}` 는 묶음 열 수로 예약돼 있어 폭으로 읽히지 않는다. 옛 표기
`![설명|480](url)` 은 폭이 아니라 **캡션에 글자로 찍힌다** — 규칙 `image-width-legacy`.

Studio 에서는 그림을 눌러 뱃지 / 좁게 / 기본 / 넓게 중에 고를 수 있다.
`{240}` 처럼 px 을 직접 적은 그림은 버튼이 켜지지 않고 현재 px 이 함께 보인다.

### 저장 위치

- 실제 파일: Supabase Storage `post-images/<slug>/foo.png`
- 마크다운 경로: `/posts/<slug>/foo.png` (앞 `/` 필수)

경로가 Storage 주소가 아닌 이유는 `next.config` 의 fallback rewrite 가 그 경로를
Storage 로 넘겨주기 때문이다 — 본문이 짧게 유지되고, 저장소를 옮겨도 글은 그대로다.
**Storage URL 을 본문에 직접 쓰지 말 것.**

업로드는 Studio 에디터(드래그·붙여넣기·툴바, dev 모드) 또는
`POST /api/posts/[slug]/images`, MCP `upload_post_image`(SVG 는 `svg`, PNG·JPEG 는 `base64`, HTML 은 `html`).

### 작동하는 HTML — ```embed

스킬이 만든 위젯처럼 **눌러 보는 결과물**은 스크린샷 대신 그 HTML 을 그대로 띄운다.
`.html` 로 올리고(`upload-image.mjs <slug> <파일>.html`) 펜스 블록에 적는다.

    ```embed
    caption: 같은 토큰 버킷 요청을 스킬 없이와 /anatomy로 만든 결과
    src: /posts/<slug>/before.html | 스킬 없이
    src: /posts/<slug>/after.html | /anatomy
    height: 560
    ```

| 키 | 뜻 |
|---|---|
| `src` | `/posts/<slug>/<이름>.html`. 둘 이상이면 `\| 버튼 이름` 으로 전·후 탭 |
| `height` | 120~2000 px. 빼면 안쪽 문서 높이에 맞춘다. 판 안은 스크롤되지 않아 이보다 긴 내용은 잘린다 |
| `caption` | 그림 아래 설명. 빼도 된다 |

- 외부 스크립트·폰트 없이 한 파일(외부 `<script src>` 는 업로드 거부, 140만 자 안쪽). 스크립트·폼만 허용한 sandbox iframe(srcdoc)에서 돌아 블로그 쿠키·저장소에 닿지 못한다. 안쪽 localStorage·alert·클립보드는 안 된다.
- 창 높이를 따르는 위젯(`100vh`, `height: 100%`, 화면 전체 absolute)은 `height:` 를 적는다.
- Storage 는 HTML 을 text/plain 으로 내준다. 주소를 직접 열면 글자로 보이는 게 정상이다.
- 문법이 틀리면 코드 블록으로 보인다 — 규칙 `embed-error`. 없는 파일은 `missing-image`.

## 10. 지원하지 않는 것

의도적으로 빠진 표기들. 필요해지면 그때 추가.

| 표기 | 왜 | 어떻게 떨어지나 |
|------|------|------|
| `> 일반 인용문` | `>` 는 callout 전용으로 고정. 한 가지 의미만. | 제목 없는 INFO 박스 |
| `> [!DANGER]` 등 | callout 은 네 종류뿐. | 대괄호 표기가 본문에 그대로 |
| `<Callout>` · `<br>` | JSX/HTML 태그. 마크다운인지 JSX 인지 모호. | 글자 그대로 출력 |
| `- [x] todo` | 체크박스. 글에 어울리는 컨텍스트가 거의 없음. | `[x]` 가 그대로 보임 |
| 들여쓴 중첩 리스트 | 2단 이상. 글이 정리가 덜 됐다는 신호. | 리스트가 아니라 단락 |
| `~~취소선~~` | 기술 본문에서 의미 부여가 어렵다. | `~~` 가 그대로 |
| `##### H5` | 파서는 H1–H4 만. | 단락 |
| `#제목` (공백 없음) | RULE-01 위반. | 단락 |

전부 `check_posts` 가 규칙으로 잡는다 → [RULES.md](RULES.md)

## 11. 에디터 툴바 (Studio)

Studio 에디터 버튼은 커서 위치에 마크다운을 삽입한다. 텍스트가 선택돼 있으면 그 텍스트를 감싼다.

| 버튼 | 출력 |
|------|------|
| 굵게 | `**텍스트**` |
| 기울임 | `*텍스트*` |
| 인라인 코드 | `` `텍스트` `` |
| 줄바꿈 | 빈 줄 한 칸 |
| 코드 블록 | ` ```java:File.java` … ` ``` ` |
| Callout — INFO / WARNING / TIP / NOTE | 종류별 버튼 4개. `> [!KIND] 제목` |
| 링크 카드 (`↗`) | 커서 자리에 카드 줄 한 줄. 선택한 텍스트가 주소면 그걸 쓴다 (§8) |
| 수평선 | `---` |

표 버튼은 없다 — 손으로 쓴다(§7-2).

## 12. 전체 예시 — 한 편 분량

````markdown
# 들어가며

JPA 를 쓰면서 한 번쯤은 의아했을 것이다 — 변경 감지(dirty checking)는
어떻게 그렇게 **가볍게** 동작할까?

```java:Order.java
Order o = em.find(Order.class, 1L);
o.setStatus(PAID);
// commit 시점에 UPDATE 가 자동으로 나간다
```

> [!INFO] 이 글이 다루는 범위
> Hibernate 6.x 기준으로 본다.
> 1차 캐시·flush·write-behind 는 이미 안다고 가정.

## 스냅샷의 정체

엔티티가 영속성 컨텍스트에 들어올 때, Hibernate 는 그 시점의
필드값을 `Object[]` 배열로 복제해 둔다. 이걸 *snapshot* 이라 부른다.

### 동작 단계

1. `em.find()` 시점에 스냅샷 한 벌을 따로 저장한다.
2. `flush()` 시점에 현재 필드와 스냅샷을 필드 단위로 비교한다.
3. 다른 필드가 하나라도 있으면 UPDATE 를 만들어 큐에 넣는다.

> [!WARNING] 주의할 점
> 스냅샷은 **필드 참조를 그대로 복제**한다.
> 컬렉션 내부를 mutate 하면 비교가 어긋난다.

자세한 건 [Hibernate User Guide](https://docs.jboss.org/hibernate/orm/6.4/userguide/) 에.

---

> [!TIP] 빠르게 끌 수 있다
> `@DynamicUpdate` 를 붙이면 변경된 필드만 UPDATE 절에 넣는다.
````

## 부록 — 파서 토큰 우선순위

`renderMarkdown` 의 라인 처리 순서 (`src/lib/markdown.tsx`):

1. 빈 줄 → skip
2. `^---+$` → `<hr>`
3. 줄 전체가 URL 또는 `/posts/slug` → 링크 카드 (§8)
4. `^#{1,4}\s+` → 헤더
5. ` ``` ` → 코드 블록 (다음 ` ``` ` 까지 raw)
6. `>` 시작 → callout (다음 비-`>` 줄까지)
7. `^-\s+` → 불릿 리스트
8. `^\d+\.\s+` → 번호 리스트 (서브 `-` 흡수 가능)
9. `|` 시작 + 다음 줄이 구분행 → 표
10. 그 외 → 단락 (다음 빈 줄/블록 토큰까지)

5번이 4번보다 뒤에 있어 보이지만, 펜스가 열리면 안쪽 줄은 블록 판정 자체를 거치지
않는다. 그래서 코드 블록 안의 `#제목` 이나 `<div>` 는 아무 규칙에도 안 걸린다.

인라인 (단락·헤더·리스트 항목·callout 본문 안에서):

1. `![alt](url)` 이미지 (alt 의 `|` 뒤가 width)
2. `[text](url)` 링크
3. 맨 `https://…` 자동 링크 (끝에 붙은 문장부호는 제외)
4. `` ` `` ~ `` ` `` 인라인 코드
5. `**` ~ `**` 굵게
6. `*` ~ `*` 기울임 (스페이스 바로 옆은 X)

이 순서를 알면 *왜 어떤 표기가 동작하지 않는지* 추측할 수 있음.
