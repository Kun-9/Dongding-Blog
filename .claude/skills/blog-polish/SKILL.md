# blog-polish — 블로그 글 다듬기

이 블로그 글은 AI가 쓴다. 지켜야 할 "쓴 사람의 말투"는 없다. 목표는 어느 글이나 같은 말투 하나로 읽히고 AI 말투가 없는 것이다.

말투 교정의 정본은 이 저장소에 있다.

- 쓰기 기준: `src/lib/voice.ts` 의 `VOICE_RULES`. 서버 `get_release_writing_guide` 가 같은 내용을 준다.
- 정규식 점검: `src/lib/phrases.ts` 의 `AVOID`. `check_release_voice`·`check_posts` 의 `stock-phrase` 로 나온다.
- 판단과 절차: 이 스킬. 정규식으로 못 잡는 것과 고치는 순서를 다룬다.

## 두 가지 일

- **고치기**(기본): 찾기 목록 → 목록의 문장만 고치기 → 점검 → 글 전체 다시 읽기. 보고는 전→후와 이유.
- **찾기만**: "AI 같은지 봐 줘", "점검만" 같은 요청. 문장마다 패턴 이름·인용·고칠 말 한 줄씩 내고 고치지 않는다. 점수를 매기거나 AI가 썼는지 추측하지 않는다.

## 1. 말투는 블로그 하나

- 본문은 합니다체, 소제목은 서술체 평서문. 기술 용어는 원래 이름 그대로 쓴다(broadcast, Durable Object, p95).
- 나머지는 평소 쓰는 일상어. 양쪽으로 새는 말을 다 고친다.
  - 구어·속어·은어: 멀쩡하다, 드문드문, 뜬다, 붙는다, 먹는다, 다시 찬다 → 문제가 없다, 가끔, 생긴다, 연결한다, 적용된다, 초기화된다
  - 보고서 한자어: 발생합니다, 소진, 간헐적, 정상적으로 동작, 휴면 → 생깁니다, 다 씁니다, 가끔, 문제없이 돕니다, 잠든
  - 번역투: 요금에 셉니다(counts toward) → 요금에 듭니다·~로 칩니다, 무료 한도 안입니다 → 넘지 않습니다, ~함으로써·~를 통해·~뿐만 아니라·~가 가능합니다
- 같은 것은 같은 이름 하나로 부르고, 이름은 코드·공식 문서를 따른다. world 는 구독 단위가 '구역', 땅 한 칸이 '칸'이라 둘을 섞지 않는다. 같은 대상을 '가짜 사람'·'가짜 탭'·'가짜 접속자'로 돌려 부르지 않는다.
- 무생물에 사람 동사를 주지 않는다. "화면이 60프레임을 지킵니다" → "화면은 60프레임이 나옵니다".

## 2. 뜻을 먼저 맞춘다

말을 고르기 전에 문장이 맞는 말인지 본다. 누가 무엇을 보내고, 받고, 세고, 내는지 문장 안에서 드러나야 한다.

- **동사의 대상**: "`acceptWebSocket`으로 받으면"(무엇을?) → "연결을 받으면". "세는 위치"(누가 무엇을?) → "요금에 드는 위치 메시지".
- **주어와 서술어**: "객체 하나는 … 권장 한도입니다", "사본이 … 사이가 … 선입니다"처럼 어긋난 문장.
- **잰 값과 계산한 값**: 다른 서비스 방식으로 환산한 수를 잰 것처럼 쓰지 않는다("들어온 위치에 복사된 위치를 더해 계산한 수").
- **시험 결과의 범위**: 내 시험 결과를 제품의 고정 한도로 넓히지 않는다. 범위는 "이 시험에서"·"이 조건으로" 한 마디로 걸고 문장은 현재형으로 단정한다. "였습니다" 보고형이나 문장마다 단서를 다는 식으로 범위를 표시하지 않는다.
- **섞지 않을 것**: 조건이 다른 시험(셋 중 한 명 움직임과 모두 움직임), 메시지 수와 요청 건수, 요금에 드는 양과 실제 전송량.
- **모호한 용어·수치**: 묻기 전에 관련 저장소의 git log·코드에서 찾는다. "진행자 서버"는 world 커밋 9cd52a7 에서 위치 중계를 부르던 이름이었다. 기록이 없을 때만 묻는다.
- 새 주장·숫자·예시·출처를 만들어 넣지 않는다. 출처가 없는 주장은 지우거나 사용자에게 묻는다.

## 3. 정규식이 못 잡는 생성 말투

`stock-phrase` 가 잡는 것은 점검 결과로 본다. 아래는 문장마다 직접 읽어 찾는다.

- 이분 대비와 부정 나열: "X가 아니라 Y", "X도 Y도 아닌 Z"를 돌려 쓴 것 → Y(Z)만 단정
- 서두 털기·아는 척·콜론 공개: "핵심은", "대부분이 놓치는", "좋은 점: ~" → 주장을 바로
- 의미 덧칠 꼬리: "~를 보여 줍니다", "~를 방증합니다" → 무엇이 어떻게 되는지
- 중요성 과장·해석 끼어들기: "중요한 역할", "보시다시피", "이 차이가 중요합니다" → 사실만 두고 지운다
- 출처 흐리기: "전문가들은", "흔히" → 이름과 링크, 없으면 지운다
- 가짜 센 동사: "~ 역할을 합니다", "구심점" → "~입니다", "~합니다"
- 같은 모양 문장 쌓기, 짧은 문장 연타, 한 문장짜리 문단이 줄줄이 이어지는 것 → 이어지는 사실끼리 문단으로 묶는다
- 수사 질문·자문자답 → 답만
- 비유·경구로 맺기, 요약으로 맺기 → 지우고 마지막 구체 문장에서 끝낸다(새 비유로 바꾸지 않는다)
- 이식 가능한 문장: 다른 제품 이름을 넣어도 성립하면 지우거나 이 주제의 숫자·동작으로 바꾼다
- 보여 주지 않고 말해 주기: "놀랍게도", "흥미롭게도" → 사실이 강조를 맡게 한다
- 형식 장식: 줄표는 글 전체 두 번 이하, 굵게는 섹션 첫 요점 문장에만, 이모지 없음

## 4. 고치는 원칙

- 목록에 오른 문장만 고친다. 목록 밖 문장을 매끈하게 다듬다 보면 수치·조건이 슬쩍 바뀐다.
- 낱말 하나만 바꾸지 말고 앞뒤 문장과 이어 읽히는 완성 문장으로 쓴다. 한 문단에 정보 단위가 둘이면(요금 계산과 객체 구조) 문단을 나눈다.
- 고친 문장이 원문보다 길면 사실 하나를 덜거나 둘로 나눈다. 접속사(하지만·반면·다만)나 설명절을 붙여 매끄럽게 만들지 않는다.
- 그림 글자(svg 제목·판 글자·caption·legend, bars caption)도 본문과 같은 말·같은 이름으로 고친다. 폭과 간격은 blog-svg 를 따른다.
- 형식 규칙은 말투 교정으로 바꾸지 않는다: 요약 박스 이름표(이런 분께·겪는 일·이렇게), 접힌 칸 제목('~려면'), 소제목 24자, 문단 숫자 셋.
- 코드·수치·측정 조건·식별자·링크 주소는 바꾸지 않는다.

## 절차

1. `get_post` 로 원문과 점검 결과를 받는다. 제목부터 끝까지 읽고 섹션마다 독자가 알고 싶은 것을 한 줄로 적는다.
2. 찾기 목록을 만든다. 문장마다 `패턴 | 인용 | 고칠 말`. 1절(말투) → 2절(뜻) → 3절(생성 말투) 순서로 본다. 사실이 걸리면 저장소에서 확인한다.
3. `update_post` 의 `replacements` 로 목록의 문장만 고친다. 같은 문자열이 여럿이면 앞뒤 문맥을 붙여 하나로 만든다.
4. `update_post` 가 돌려준 점검과 `check_release_voice` 를 본다. 고치다 생긴 경고(heading-long, number-dense, stock-phrase)는 그 자리에서 다시 고친다.
5. 글 전체를 다시 읽는다. 바꾼 문장 때문에 주어·조건·이름이 어긋난 곳, 같은 결론을 두 번 말하는 곳을 찾는다.
6. 두 글 이상에 나올 패턴이면 `src/lib/phrases.ts` 의 `AVOID` 에 정규식으로 더한다. `node .claude/skills/blog-polish/scan.mjs '<정규식>'` 으로 글 전체에 돌려 오탐을 보고, 참·거짓 예문을 `scripts/check-voice-rules.mjs` 에 넣는다. 쓰기 기준 문장은 `VOICE_RULES` 에 더한다. 저장소 규칙대로 워크트리 → ff 병합 → push.
7. 보고한다: 고친 곳 전→후와 이유(어떤 결합이 어긋났나, 무엇이 겹쳤나), 버린 제안과 이유, 남은 점검 결과.

## 보고 전 점검표

- 뜻·주장·수치를 더하거나 바꾸지 않았다.
- 모든 문장이 블로그 말투다. 구어·보고서 한자어·번역투가 남지 않았다.
- 같은 것은 한 이름이고, 동사마다 대상이 있다.
- 계산한 값과 잰 값, 시험 결과의 범위가 구분된다.
- 고친 문장이 원문보다 길지 않다.
- 점검에 새 경고가 없다.
- 글 전체를 다시 읽었다.
