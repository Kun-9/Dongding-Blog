# 블로그 svg 그림

흐름·구조(무엇이 어디로 가고, 어디서 세어지고, 어디서 막히나)는 본문에 ```svg 블록으로 직접 그린다. 숫자·표·파일 트리·화면 재현은 이 스킬이 아니라 blog-figures 의 그림 블록·```figure 로 그린다.

기준은 셋이다(2026-11-10 사용자 지시). **그림만 보고도 이해된다, 간격과 여백이 넉넉하다, 그림 글자에도 AI 말투가 없다.** 글자를 덜어 내기만 하면 정보가 사라져 그림이 본문에 기댄다(2026-11-10 첫 시안이 그랬다). 덜어 낼 것은 설명 문장이고, 사실은 남긴다.

## 1. 그리기 전에 네 줄

셋째 줄까지 안 나오면 그림이 아니라 문장이다.

1. **결론** — 그림을 보고 가져갈 한 문장. `title:` 이 된다('~다', 40자 안팎).
2. **움직임** — 독자가 문장으로 조립해야 하는 움직임. 그것이 선이 된다(복사된다 → 부채꼴, 막힌다 → 관문 앞 X, 돌려준다 → 되돌아오는 화살표).
3. **갈리는 곳** — 어디서 막히거나 세어지나. 비교면 같은 배치 두 판에서 그 선(색, 있고 없음)만 다르게.
4. **결과** — 그 결과로 무엇이 얼마인가(20통, 403, 5MB에서 끊김). 그림 안에 숫자나 응답으로 넣는다.

그다음 `samples.md` 에서 가장 가까운 견본을 골라 좌표와 글자를 고친다.

## 2. 그림만으로 읽히게

본문을 가리고 제목·그림·캡션만 보여 줬을 때 제목 문장이 왜 참인지 그림에서 손으로 짚을 수 있어야 한다. 그러려면 그림에 이 넷이 다 있다.

| 무엇 | 그림에서 | 예 |
| --- | --- | --- |
| 누가·무엇이 | 상자 이름은 본문의 고유 이름 그대로 | 지수, API 서버, `mcp__team` |
| 무엇이 오가나 | 선마다 오가는 것의 이름(명사 + 필요하면 짧은 동사) | 위치 1통, 이미지 URL 요청, 받은 바이트 |
| 어디서 갈리나 | 표시(mark-x·mark-ok, bad·good 색) + 이유 한 마디 | 403, 내부 주소, 앞부분만 비교 |
| 결과 | 숫자·응답·상태를 그림 안에 | 20통 / 1통, 5MB에서 끊긴다 |

- **둘째 줄은 사실일 때만 둔다.** 숫자, 설정 키, 조건처럼 그림만 볼 사람에게 필요한 사실이면 상자·선 이름 아래 `sm`·`xs` 한 줄로 둔다. 이유 풀이·설명 문장은 본문으로 보낸다.
- 조건(언제, 무엇을 할 때)은 `caption:` 한 줄. 색의 뜻은 `legend:`.
- 생각은 그림 하나에 하나. 상자 6개, 선 이름 8개를 넘으면 판을 둘로 나누거나 그림을 둘로.

## 3. 간격과 여백

수치는 viewBox 단위(휴대폰에서 거의 1px)다. 8 을 기본 단위로 쓴다.

| 자리 | 최소 | 메모 |
| --- | --- | --- |
| 상자 안쪽 좌우 | 12(상자 폭 = 가장 긴 줄 + 24) | 6 아래면 svg-text-box |
| 상자 높이 | 한 줄 40, 두 줄 56 | 두 줄은 줄 간격 18 |
| 상자와 상자 사이 | 가로 56, 세로 64 | 사이 선에 이름이 들어가면 이름 폭 + 24 |
| 선 이름과 선 | 6~8 | 가로선은 위쪽, 세로선은 오른쪽. 선의 가운데. 선이 글자를 지나면 svg-line-text |
| 글자 줄 간격 | 14 → 20, 12.5 → 18, 12 → 17 | 더 붙으면 svg-text-tight |
| 덩어리 사이 | 28 | 판 이름 ↔ 그림 ↔ 결과 숫자 줄 |
| 판 가장자리 | 글자·선이 viewBox 끝에 닿지 않게 4 | 판 둘레 여백은 CSS 가 준다 |

빈자리를 무서워하지 않는다. 판을 채우려고 글자를 늘리지 않고, 남는 폭은 상자 사이를 넓히는 데 쓴다. 판 폭이 모자라면 글자를 줄이지 말고 판을 키우거나(360 까지) 세로로 쌓는다.

## 4. 그림 글자의 말투

그림 글자도 글이다. 본문과 같은 생성 말투 규칙(쓰기 기준, `src/lib/phrases.ts`, no-ai-slop 에서 옮긴 패턴)을 제목·판 이름·선 이름·캡션에 건다. 점검 `svg-text-slop` 이 정규식으로 잡히는 것을 알린다.

- **제목:** 결론을 그대로 단정한다. "X가 아니라 Y"(이분 대비), "핵심은 ~", 콜론 공개("이유: ~"), 수사 질문, 과장("완전히", "결정적") 없이.
- **선·상자 이름:** 명사나 짧은 동사. 비유, 말장난, 번역투("~에 의해", "~를 통해"), em 대시(—) 없이. 영어는 고유 이름과 코드만.
- **되풀이 금지:** 제목·판 이름·캡션이 같은 말을 돌려 말하지 않는다. 캡션은 조건, 판 이름은 방식 이름, 제목은 결론.
- **정규식이 못 잡는 것:** 같은 것을 다른 말로 부르기(한 판은 "사본", 다른 판은 "복제본"), 같은 모양 문장 쌓기. 그림 글자를 한 줄씩 읽고 no-ai-slop 의 detect 방식(패턴 이름·인용·고칠 말)으로 목록을 만든 뒤 그 줄만 고친다.
- 남의 글을 예문으로 옮겨 보이는 줄(말투 비교 그림 등)은 `class="q"` 를 달아 점검에서 뺀다.

## 5. 문법

````
```svg
title: curl은 WebFetch 규칙을 거치지 않고 샌드박스에서 막힌다
caption: aka.ms 만 허용했을 때
legend: x=막힘
<svg viewBox="0 0 320 120">
  <text class="b" x="0" y="18">Bash로 curl</text>
  <circle class="dot" cx="6" cy="60" r="3"/><line class="edge" x1="10" y1="60" x2="128" y2="60"/>
  <text class="xs mid" x="68" y="52">aka.ms 요청</text>
  <rect class="soft bad" x="136" y="40" width="132" height="40" rx="8"/>
  <text class="sm b ink mid" x="202" y="65">샌드박스 프록시</text>
  <circle class="mark-x" cx="136" cy="60"/>
  <text class="xs bad" x="280" y="64">403</text>
</svg>
```
````

- **머리 줄:** `title:`(필수, 그림 위), `caption:`(조건, 그림 아래), `legend: bad=요금에 세는 메시지; x=막힘; ok=통과; dash=일부만`(키 bad·good·accent·muted·dash·x·ok·dot).
- **판:** `<svg viewBox="0 0 W H">` 하나가 판 하나. W 360 이하, 휴대폰에서 1배 가까이 보이려면 320. 두 판을 넓은 화면에서 나란히 보이려면 W 300 안쪽(판이 0.92배 아래로 줄 자리면 쌓인다). 그보다 넓은 그림은 `data-only="wide"`(W 640 이하, 판 안쪽 600px 이상에서만 보임) 판과 `data-only="narrow"` 판을 같이 두고, 좁은 판은 세로로 다시 그린다.
- **요소:** g rect circle ellipse line polyline polygon path text tspan. 그 밖의 태그, `fill`·`stroke`·`style`·`font-size` 속성, `on*` 은 지워진다(figure-dropped). 색·크기는 클래스로만 칠해 다크 모드가 따라온다.
- **클래스:** 글자 `sm`(12.5)·`xs`(12, 가장 작음)·`lg`(16 굵게)·`xl`(28, 핵심 숫자)·`b`·`mono`·`mid`·`end`·`ink`·`muted`·`q`(옮긴 예문), 모양 `box`·`soft`·`zone`·`edge`·`thin`·`dash`·`faint`·`dot`, 뜻 색 `bad`(막힘·요금)·`good`(통과)·`accent`(지금 이야기하는 것 하나). 글자 기본은 14. 목록과 뜻은 `src/lib/svg-figure.ts` 의 `SVG_CLASS_DOC`.
- **표시:** 화살촉 `marker-end="url(#a)"`(a-bad·a-good·a-muted). `<circle class="mark-x" cx cy/>`·`mark-ok` 는 원과 X·체크를 함께 그린다.
- **글자 폭:** svg 는 줄을 접지 않는다. 한글 한 자는 글자 크기만큼(14 → 14), 영문·숫자는 그 0.6, 고정폭은 0.6. 길면 `<tspan x="…" dy="18">` 로 두 줄.
- 움직임은 없다. 멈춘 한 장으로 읽혀야 한다.

## 6. 확인

워크트리(또는 저장소) 뿌리에서 돌린다.

```bash
node_modules/.bin/jiti .claude/skills/blog-svg/check.ts <글.md>             # 그림마다 점검(경고 0 이 될 때까지)
node_modules/.bin/jiti .claude/skills/blog-svg/shot.ts <글.md> <출력 폴더>   # 390 라이트·390 다크·760 캡처
```

- `check.ts` 는 본문 점검기와 같은 규칙을 그림 단위로 돌린다: svg-title-claim(결론 문장인가), svg-text-out(판 밖 글자), svg-text-box(상자 안쪽 여백), svg-text-tight(글자끼리 붙음), svg-line-text(선이 글자를 지남), svg-no-edge(선 없는 상자), svg-text-slop(그림 글자 말투), diagram-error·figure-dropped.
- 글자 폭은 어림이다. 경고가 없어도 `shot.ts` 캡처를 열어 본다: 휴대폰에서 글자가 11px 아래로 줄지 않는지, 덩어리 사이가 비어 보이는지, 다크에서 선·글자가 보이는지.
- 마지막으로 캡처만 보고 1장의 네 줄(결론·움직임·갈리는 곳·결과)이 다 짚이는지 본다.
