Markdown 가이드

Studio 미리보기와 글 상세는 같은 파서를 공유한다. 이 문서가 그 grammar의 전부 — 여기 없는 표기는 동작하지 않는다.

Parser · markdown.jsx Scope · Studio · 글 상세 Updated · 2026.08.09 Version · v1.3.0

01개요

왜 한 벌의 마크다운인가, 그리고 이 문서를 읽는 법.

이전엔 Studio 미리보기 파서가 따로, 글 상세는 JSX로 직접 작성하는 구조였다. 결과적으로 같은 글이 두 화면에서 다르게 보이는 일이 잦았다 — 미리보기에서는 callout이 깨지고 상세에서는 멀쩡한 식. v1.3.0부터 markdown.jsx 한 벌이 양쪽을 담당한다.

그래서 이 문서에 적힌 표기만 동작한다. <Callout> 같은 JSX 태그, GitHub Flavored Markdown의 표·체크박스, HTML 직접 임베드 — 전부 일반 텍스트로 떨어진다. 의도적으로 좁게 잡았다. 작성하는 사람이 머릿속에 담을 수 있는 양.

02기본 규칙

먼저 알아두면 디버깅 시간이 줄어든다.

RULE-01

마커 뒤엔 공백 한 칸

# 제목, > [!INFO], - 항목 — 모두 마커 다음에 공백이 와야 한다. #제목은 그냥 단락.

RULE-02

>는 callout 전용

일반 인용문(blockquote)은 지원하지 않는다. >로 시작하는 줄은 항상 callout으로 해석된다.

RULE-03

JSX 태그는 안 받는다

<Callout>, <br> 같은 태그는 그대로 텍스트로 출력된다. 마크다운인지 JSX인지 모호해지는 걸 막기 위해.

RULE-04

블록 사이엔 빈 줄

헤더·코드 블록·callout·리스트 사이에는 빈 줄을 한 줄 두는 게 안전하다. 없어도 대부분 동작하지만 단락이 들러붙는 경우가 생긴다.

11전체 예시

실제 글 한 편 분량의 마크다운. 위 표기가 어떻게 어우러지는지.

# 들어가며

JPA를 쓰면서 한 번쯤은 의아했을 것이다 — 변경 감지(dirty checking)는
어떻게 그렇게 **가볍게** 동작할까?

```java:Order.java
Order o = em.find(Order.class, 1L);
o.setStatus(PAID);
// commit 시점에 UPDATE가 자동으로 나간다
```

> [!INFO] 이 글이 다루는 범위
> Hibernate 6.x 기준으로 본다.
> 1차 캐시·flush·write-behind는 이미 안다고 가정.

## 스냅샷의 정체

엔티티가 영속성 컨텍스트에 들어올 때, Hibernate는 그 시점의
필드값을 `Object[]` 배열로 복제해 둔다. 이걸 *snapshot*이라 부른다.

### 동작 단계

1. `em.find()` 시점에 스냅샷 한 벌을 따로 저장한다.
2. `flush()` 시점에 현재 필드와 스냅샷을 필드 단위로 비교한다.
3. 다른 필드가 하나라도 있으면 UPDATE를 만들어 큐에 넣는다.

> [!WARNING] 주의할 점
> 스냅샷은 **필드 참조를 그대로 복제**한다.
> 컬렉션 내부를 mutate하면 비교가 어긋난다.

자세한 건 [Hibernate User Guide](https://docs.jboss.org/hibernate/orm/6.4/userguide/)에.

---

> [!TIP] 빠르게 끌 수 있다
> `@DynamicUpdate`를 붙이면 변경된 필드만 UPDATE 절에 넣는다.
