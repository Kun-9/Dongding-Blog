개발 노트, 다시 짓다

자바와 스프링, DB를 깊이, 천천히 따라가는 1인 기술 블로그를 위한 제품 요구사항. 목적 · 사용자 · 페이지 · 결정 로그를 한 곳에서.

01개요

한 페이지로 압축한 제품 요지.

Dong-Ding은 2년차 백엔드 개발자 1인의 기술 블로그입니다. 흔한 "TIL" 모음이 아니라, 한 주제를 깊이 따라가는 글을 모아두는 곳을 목표로 합니다. 빠르고, 광고가 없고, 다크모드를 지원하고, 코드 블록이 부끄럽지 않게 잘 보이는 — 그게 전부입니다.

i
한 줄 요약 — 자바와 스프링, DB에 대해 천천히 깊이 쓰는 글을 모아두는 곳. 작성자가 다시 와서 검색해 읽을 수 있어야 한다.

02배경 · 왜 만드는가

기존 플랫폼으로는 안 되는 이유.

문제

  • velog · tistory — 글이 "스트림"으로만 흐르고 시리즈/연재 구조가 약합니다. 한 주제를 5편으로 쓰면 세 번째 글에서 흐름이 끊깁니다.
  • medium — 코드 블록 가독성이 떨어지고, 한국어 본문 글꼴 옵션이 빈약합니다.
  • github pages 템플릿 — 만들면 디자인이 어딘가 어색하고, Tailwind를 쓰지 않으면 새 페이지를 추가할 때마다 CSS를 다시 고민해야 합니다.
  • 공통 — 검색 결과 페이지, 어드민, 글 작성 인터페이스가 작성자 본인의 글쓰기 동선에 맞지 않습니다.

기회

독자에게는 읽기 좋은 페이지를, 작성자에게는 다시 쓰고 싶은 작성 환경을 만들 수 있다면, 한 주에 한 글이라는 페이스를 1년 이상 유지할 수 있다고 가정합니다. 이 가정이 곧 이 프로젝트의 출발점입니다.

03목표 · 비목표

하기로 한 것과, 하지 않기로 한 것.

목표 (Goals)

G1
읽는 즐거움 — 본문 타이포그래피와 코드 블록을 1순위로.
G2
시리즈/연재 구조 — 한 주제를 여러 편으로 묶어 보여줄 것.
G3
작성 동선 — 마크다운으로 빠르게 쓰고 라이브 프리뷰로 확인.
G4
다크모드 동등 — 라이트와 동등한 품질의 다크 테마 제공.
G5
한국어 우선 — 글꼴, 줄바꿈, 자간을 한국어 본문에 최적화.
G6
광고/추적 없음 — 외부 트래커, 디스플레이 광고 일체 미설치.

비목표 (Non-goals)

  • 다중 작성자를 지원하지 않습니다. 1인 블로그를 전제합니다.
  • SNS형 상호작용 (좋아요, 팔로우, 알림 피드)을 만들지 않습니다.
  • 수집 파이프라인을 직접 만들지 않습니다 — 방문 집계는 Umami에 위임하고, /admin/stats는 그 공유 링크를 읽어 보여주기만 합니다.
  • SEO 광적 최적화는 하지 않습니다. 사이트맵·OG·canonical 정도만.
  • 모바일 앱을 만들지 않습니다. 모바일 웹에서 읽기 좋게.
!
비목표는 의식적으로 보호한다. "기왕이면 추가해도 좋잖아?"라는 말이 들리면, 이 섹션을 다시 펴고 거절한다.

└ /sitemap.xml public

네비게이션 원칙

  • 헤더는 아바타 + 4개 링크 (Posts · Series · Linkroll · About) + ⌘K + 테마 토글. 카테고리는 헤더가 아니라 홈 하단과 목록 사이드바에서 만납니다 — 5개가 늘어날 여지가 있어 헤더에 고정하지 않습니다.
  • Series · Linkroll은 헤더에 명시합니다 (DEC-10). ⌘K만으로는 "그 페이지가 존재함"을 알릴 수 없습니다.
  • Admin · Studio · Stats · Settings는 로그인했을 때만 계정 드롭다운 안에 나타납니다 (DEC-16). 로그아웃 상태에서 직접 접근하면 /login으로 대체되고, 실제 차단은 서버가 합니다.
  • 글 단위 관리자 액션(수정·복제·삭제)은 메뉴가 아니라 그 글 위 AdminBar에 둡니다 (DEC-09).

06페이지 사양

각 페이지의 목적과 핵심 컴포넌트.

PATH · 이름 목적 · 핵심 요소
/
홈		 에디토리얼 히어로 · 피처드 1편(+ 리드 그림 3단 폴백) · 최근 글 6편 그리드 · Trending 5편 · 카테고리. 첫인상이 곧 신뢰.
/posts
글 목록		 연도별 그룹 · 카테고리 pill 필터. 옛날 글로 거슬러 가는 동선.

상세		 본문 + sticky TOC + reading progress · 코드블록(파일명·복사·하이라이트·diff) · Callout 4종 · 조회수 · 좋아요 · Giscus 댓글 · 시간순 이전/다음. 시리즈 글이면 상단 배너 + 하단 스텝 네비가 추가됩니다.

소개		 짧은 자기소개 · 경력 타임라인 · 관심사 · 연락처. About은 짧을수록 좋다.

07디자인 결정 로그

왜 이렇게 했는가 — 선택의 기록.

DEC-01

크림 베이스 (#f7f4ed)

한국 기술 블로그가 대부분 새하얀 배경을 쓰기 때문에, 의도적으로 크림 톤을 베이스로 잡습니다. 종이 같은 인상 → 글을 읽는 환경.

keptvisual
DEC-02

Pretendard 본문 + JetBrains Mono 코드

한국어 본문에 가장 안정적인 글꼴. Source Serif 4를 강조용으로 잠깐 검토했지만 코드/한글 혼용에서 어울리지 않아 폐기.

keptSource Serif: 폐기
DEC-03

선택 상태에 좌측 컬러 바를 쓰지 않는다

TOC 활성 항목, 카테고리 사이드바 활성 항목, Callout — 모두 좌측 2~3px 컬러 바를 빼고 배경색·아이콘으로만 강조. AI 시안 트로프와 거리두기.

kept2026.04.27
DEC-04

코드 블록 — 카드 vs 미니멀, 둘 다 제공

본문 흐름이 우선인 사람과, 코드 강조가 우선인 사람을 모두 만족시키기 어렵다. Tweaks 패널에서 토글로 전환 가능하게.

kepttweak
DEC-05

word-break: keep-all 전역 적용

한국어 본문에서 단어 중간 줄바꿈을 막는 가장 단순한 해법. 다만 좁은 flex 컨테이너에서는 따로 whiteSpace: nowrap으로 보호.

kepti18n
DEC-06

댓글 — Giscus, 자체 구현 ✗

독자 풀이 작은 1인 블로그에서 댓글 DB를 직접 만들 이유가 없다. GitHub Discussions에 위임.

keptscope
DEC-07

검색 — 클라이언트 측 필터, Algolia ✗

글 200편까지는 클라이언트에서 충분. 200편을 넘기면 그때 다시 검토. 지금부터 Algolia를 도입할 이유 없음.

keptAlgolia: 보류
DEC-08

분석 — Umami

광고/추적 없음 원칙과 호환. GA4를 검토했으나 쿠키 동의 배너가 필요해 폐기. Plausible로 시작했다가 Umami로 옮겼다 — 셀프호스팅 가능하고 공유 링크(read-only)를 그대로 읽어 /admin/stats를 만들 수 있어, 지표를 보러 외부 대시보드로 나가지 않아도 된다.

keptGA4 · Plausible: 폐기v1.3.0
DEC-09

관리자 UI는 한 곳에 모아 두지 않는다

1인 운영이라도 "관리자 구역"을 /admin에만 가두면 실제 편집은 느려진다. 희관 동작에 따라 관리자 액션을 퍼뜨린다: 헤더 우측에 `＋ 새 글`로 적는 흐름 진입, 포스트 상세 상단에 AdminBar(수정/복제/삭제)로 그 글을 다루는 흐름 진입. /admin은 총괄 대시보드 역할만 유지. 관리자 표면은 대시 테두리 (`로컬 · ADMIN` 점 + dashed border)로 일반 독자 화면과 시각적으로 구분.

kept2026-04-27
DEC-10

Series · Linkroll은 헤더에 올린다

⌘K 명령팔레트만으로는 "해당 페이지가 존재함"을 알릴 수 없다. Posts/About 염에 Series, Linkroll을 명시적으로 노출. 명령팔레트는 계속 "빠른 재방문" 투스로 존재.

kept2026-04-27
DEC-11

파괴적 액션은 인라인 컨펌이 아니라 모달로

이전엔 삭제 버튼 옆에 "정말? / 삭제 / 취소"를 인라인으로 띄웠다. 클릭 한 번으로 끝나는 가벼움은 좋았지만 ⓐ 무엇을 삭제하는지 다시 보여주지 않고 ⓑ 부주의한 클릭을 막는 마찰이 거의 없다. 발행된 글 삭제는 외부 링크에 404를 만든다 — 그만한 무게를 줘야 한다. 결정: 삭제는 항상 `ConfirmDialog`(중앙 카드 + backdrop blur + danger 톤). meta 블록에 제목·slug를 다시 노출. 비파괴 액션(복제 등)은 그대로 인라인 + 토스트 피드백. 컴포넌트는 시리즈·링크롤 삭제에서도 재사용한다.

keptv1.2.1
DEC-12

마크다운 문법은 한 벌, 파서도 한 벌

Studio 미리보기와 실제 글 상세에 서로 다른 렌더 경로를 두면 글이 두 번 어긋난다 — 미리보기에선 callout이 깨지고 상세에선 멀쩡한 식. 결정: 공용 파서 `markdown.jsx`를 만들고 양쪽이 같은 grammar를 공유. 문법은 GitHub/Obsidian 친숙도를 우선해 `> [!INFO|WARNING|TIP|NOTE] 제목` + 멀티라인 callout, ` ```lang:filename ` 코드 블록, H1~H4, 리스트, 링크/이미지, `**bold**` / `*em*` / `` `code` ``, `---`로 정리. `>`는 callout 전용 — 일반 인용문은 디자인상 거의 안 쓰고, 헷갈림을 줄이려 한 가지 의미로 고정. <Callout> 같은 JSX 태그는 의도적으로 미지원(글이 마크다운인지 JSX인지 모호해짐).

keptv1.3.0
DEC-13

카테고리는 /admin이 아니라 /settings에서 관리한다

카테고리는 "구조"에 가까운 설정이다 — 한 번 정하면 자주 안 바뀌고, 바뀌면 사이트 전반(헤더 메뉴, URL, 글 매핑)에 파급된다. /admin은 발행/초안 흐름의 일상 도구로 두고, 구조 변경은 /settings에 모은다(프로필·SEO·발행 정책과 같은 결). 트리 형태(대분류 + 서브)로 인라인 편집·순서변경·추가/삭제. 글이 매핑된 카테고리는 한 번 더 묻는 2단계 컨펌(💀 모달까진 아님 — 미배포 가벼운 마찰만). ID 변경 시 URL이 깨지므로 ID 필드를 별도 줄에 노출해 의식적으로 만지게 한다.

keptv1.2.1
DEC-14

아바타는 사진이 아니라 일러스트 마크로

08기술 스택

  • 검색 — 클라이언트 측 필터 (DEC-07). 글 200편까지는 충분.
